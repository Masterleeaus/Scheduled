# Pass 35 — Installer key and completion safety

## Scope
The installer needed a stable `APP_KEY` **before** the first Laravel request/session, not a new key generated by the environment wizard. The prior wizard changed the key after framework bootstrapping, putting subsequent session cookies and setup-state continuity at risk.

## Changes
- Bootstrap `InstallerBootKey` initializes a strong key on first application boot before the framework loads `.env`.
- Uses exclusive file locking, preserves a configured key, and never changes the key on an already installed application.
- Fresh `.env` initialisation forces `APP_ENV=production` and `APP_DEBUG=false`.
- Environment wizard reuses the original key and refuses an inconsistent runtime/configuration key.
- Environment write now checks byte count and uses exclusive write lock.
- Finish route verifies a valid key, environment file, writable storage and exactly one active administrator before writing the installed marker.

## Not done / acceptance gates
No live database or web server exists here for a real installer walkthrough. The installed marker is still dependent on SQL-import and admin creation. Existing installer SQL, licence validation, migrations, mail/Stripe/Cleanto bootstrap and web server access controls require separate live verification. The environment wizard is still a legacy file writer, not a complete deployment orchestrator.
